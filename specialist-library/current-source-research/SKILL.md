# Current Source Research

State the question and decision it supports. Prefer official docs, source files, manifests, release notes and advisories. Read the actual relevant implementation/skill and consequential helpers before adoption. Separate main-branch code, release tag, package-registry version and runtime testing. Use community reports for friction, not primary capability proof. Cite exact paths/pages and dates, compare the default to a small number of credible alternatives, and label unverifiable facts. Do not download or execute a project to infer trust. Return a recommendation, supporting evidence and limitations rather than a catalog.
