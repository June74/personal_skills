# Design System

Inspect existing tokens/components and real repeated states before adding tooling. Keep one prototype/design procedure; do not install overlapping design frameworks. Choose local HTML/component preview first; Penpot for durable editable design and Storybook for a reusable component catalog when needed. Explain added services/packages and telemetry. Match design bridge/client versions and restrict file/tool scope. Define semantic tokens, component states, accessibility and visual/functional acceptance. Approve screenshot baseline changes deliberately and keep design sources editable.
