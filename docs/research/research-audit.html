Evidence appendix — repository and implementation audit

Research cutoff: 2026-09-20. This appendix records why the report's choices are supportable; it is not another installation list. It consolidates the skills, memory, and visual/voice research memos. Official client configuration and Agent Skills specification checks appear in the main report.

These were read-only inspections of documentation, release pages, manifests, selected skill bodies, and consequential helpers. Nothing was installed or executed. “Observed release” means the newest release visible in the inspected source; it is not a guarantee that no later release existed. main/develop links are mutable snapshots. Cached commit pages sometimes lagged release pages, so dated commits below establish activity, not current HEAD. A release date, push timestamp, and commit date are different evidence. Stars were not used as a quality score.

Evidence from actual skills and helpers

  • TDD: Matt's actual skill, tests.md, and mocking.md emphasize vertical slices, public interfaces, and independent expected values. The current body postpones refactoring to review despite broader README terminology; the report proposes restoring small refactoring after green. This is a deliberate adaptation, not a verbatim upstream promise.
  • Debugging: Superpowers' skill, root-cause reference, and find-polluter.sh were read. The helper assumes Bash/npm, splits filenames on whitespace, and suppresses test errors. An environment-dump example needs replacement with redacted presence checks. No general Windows/Python suitability was inferred.
  • Skill evaluation: Anthropic's skill-creator, aggregation/evaluation/description-loop scripts, schemas, and viewer generator were examined. Trigger evaluation invokes Claude CLI and writes temporary Claude commands, requiring adapters elsewhere. The viewer inserts generated JSON into HTML and may terminate the process occupying its port. Reported escaping and related viewer issues were not reproduced; this supports a simpler text/JSON review first, not a claim of a complete security audit.
  • Continuous learning: ECC's skill, hooks/observe.sh, scripts/instinct-cli.py, and agents/observer.md expose real capture and background-analysis behavior. Recording and analysis are separate controls. The documented native Windows observer limitation matters; complete redaction was not established. Compound's ce-compound contributes a useful filter for verified, non-obvious lessons, but its full reference chain was not audited.
  • Design: Anthropic's frontend-design body is compact and script-free. Impeccable's shape/craft-floor/critique references and launcher reveal a native engine, cached binary download, checksum check, and execution. Modern Impeccable cannot accurately be described as only Markdown prompts.
  • Specialists: VoltAgent's security-auditor specifies read/search tools; architect-reviewer includes Write/Edit/Bash. Both inherit models. README generalizations do not substitute for exact frontmatter or client-enforced permissions.
  • Codebase visualization: Understand-Anything's skill can install/build prerequisites, redirect worktree output, and launch many analyses. Its incremental helper genuinely filters structural changes and writes JSON atomically. Node/pnpm/Python plus parser/dashboard dependencies distinguish it from a lightweight memory store.

Other inspected bodies support the teaching workflow without implying turnkey portability. Matt's teach creates a multi-session course workspace and disables model invocation upstream; the proposed mentor skill is a smaller adaptation for everyday development. His prototype, UI.md, and LOGIC.md distinguish visual alternatives from logic exploration and avoid default persistence. His codebase-design body was read, but its deeper design references were only identified. They should not be copied under an “audited” label.

Superpowers' writing-plans includes implementation detail and framework handoffs that the proposed compact planning skill deliberately removes. The inspected requesting-code-review skill and reviewer template support independent review, while verification-before-completion concerns evidence for completion claims. This is why the report keeps those responsibilities distinct instead of activating several overlapping QA personas. These adaptations require authored files and evaluation; research did not produce an installed skill library.

Dependency inspection also distinguished optional capability from mandatory setup. K-Dense's scikit-learn examples do not require a scientific environment for ordinary application development. Handy's source-build manifest does not turn its compiler toolchain into a binary-install prerequisite. Penpot's inspected Compose file includes multiple services; calling it self-hosted does not make its maintenance equivalent to a static sketch. Unity's workflows reference is large and includes fresh-scene examples; those examples need scope checks before use on existing scenes. Blender skills from other repositories use connector-specific tool names, so their presence in a directory does not prove compatibility with the selected bridge.

The remaining portability work is concrete: translate client-specific frontmatter and invocation rules, verify discovery and routing, constrain permissions in each client, and test the same examples. Shared Markdown syntax alone establishes none of those behaviors. Likewise, separate context is useful for a bounded reviewer or codebase investigation, but an agent title does not establish isolation, durable memory, or authorization.

Browser, design, voice, and editor versions

Playwright CLI v0.1.21, September 18, and Playwright v1.63.0, September 4, were observed; both are Apache-2.0. The CLI's inspected main manifest pins a 1.64 alpha Playwright build. That is not permission to upgrade a project's stable test dependency silently.

The actual CLI skill, session and tracing references establish persistent/named sessions, file-backed output, screenshots, and scoped snapshots. Therefore “CLI is stateless” is false. Claimed token savings were not benchmarked. Trace files can contain headers, bodies, screenshots, and console data; saved regression tests remain distinct from exploratory agent browsing.

Chrome DevTools CLI documentation labels that interface experimental; the README documents usage statistics on by default and separate CrUX controls. No exact latest release was established. Agent-browser's main manifest showed 0.38.1 and Node >=24; browser-use's main manifest showed 0.13.10, Python >=3.11, and MIT. These are source versions, not verified release tags.

Other dated checks: MIT Handy v0.9.7, September 18; MIT whisper.cpp v1.9.4, September 11; MPL-2.0 Penpot 2.17, July 8. Handy's release binary avoids its source-build Rust/Bun/C++ prerequisites. Optional transcript cleanup sends text to the configured endpoint; local speech recognition alone does not establish cleanup privacy.

The old Penpot MCP was archived February 3 and moved into Penpot's monorepo; functionality was not abandoned. Unity MCP's inspected main manifests show 10.2.0, while README's dated 10.0.0 is June 30; latest published release was not independently established. Its MIT bridge license does not license Unity itself. Blender MCP's manifest shows MIT/2.0.0 and package rename mcp-for-blender; default telemetry consent and optional asset services require separate decisions.

The tagged Basic Memory CLI confirms --transport streamable-http --host 127.0.0.1 --port 8000 --path /mcp. Its default host is wildcard. Official deployment documentation states HTTP/SSE is unsecured; no native local bearer-token configuration was established. Thus the proposed endpoint is a trusted-account loopback pilot, not secure multi-tenancy.

Tagged configuration enables semantic search when included packages are present; explicitly disable it for the lexical pilot. Disabling functionality does not remove dependencies. The tagged server drains pending Markdown materializations on graceful shutdown: accepted writes may not yet exist in note files. Quiesce, drain, and preserve notes/configuration/consistent database state rather than assuming instantaneous note-only backups suffice.

Two lifecycle corrections are material: a Mem0 maintainer announced OpenMemory's sunset March 26, while core Mem0 remains active; Letta's old home redirects current development to Letta Code and retires the V1 Python server. Reusing historical deployment tutorials would recommend the wrong software.

Limits carried into the recommendation

Direct dependency counts exclude transitives, models, services, and platform packages. No three-client concurrent-write test, Windows/WSL installation, restore test, latency/token measurement, malware scan, or complete supply-chain audit occurred. Reported bugs were evidence to investigate, not reproduced findings. Local storage still exposes retrieved text to whichever hosted coding model receives it. Proposed retention schemas, evaluation adapters, approval queues, and thin SQLite/MCP services are design work, not shipped integrations. The report's staged pilot and fallback to curated files follow from these limits.
