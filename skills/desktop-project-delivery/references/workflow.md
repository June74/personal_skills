# Desktop project delivery

Resume at the current stage; scale the workflow to the actual change.

1. Recover current requirements, accepted design, and completion criteria.
   Distinguish historical plans from implemented behavior.
2. Probe uncertain platform boundaries before committing to their design.
3. Define minimal interfaces and deliver one working end-to-end path.
4. Expand through bounded slices with observable acceptance checks.
   If delegation is authorized, assign one writer per shared checkout and
   explicit ownership for interfaces, integration, and scarce resources.
5. Connect the accepted UI to real commands, events, and persisted settings.
6. Verify recovery, cancellation, expiry, and external side effects.
7. Run a real-host walkthrough; convert discovered gaps into credible tests.
8. Package and check the retained artifact independently.
   Perform cleanup only within the authorized scope.
9. Record final revision, run instructions, actual evidence, skipped checks,
   open findings, and superseded decisions.
